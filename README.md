## Запуск

Python 3.8+, без зависимостей.

```
python solution.py
```

Карта и ответы судьи читаются из stdin, команды пишутся в stdout. Карту можно передать файлом через `--map map.txt`.

Для проверки есть `judge.py`. Это простой локальный судья, он запускает решение и отвечает ему по протоколу из условия. Прогоны из примера:

```
python judge.py examples/example.map --world х1=1,х2=0,х3=1
python judge.py examples/example.map --world х1=0,х2=1,х3=1
python judge.py examples/expensive.map --world х1=0,х2=0,х3=0
```

Должно получиться 38, 38 и 0, как в условии. Можно погонять на случайных картах

```
python judge.py --random 40 --games 15 --policy index
```

Флаги solution.py
* `--policy rollout|index|noclear` стратегия, по умолчанию rollout
* `--budget 0.5` сколько секунд думать над одной расчисткой
* `--map file` карта из файла
* `--verbose` писать решения в stderr

## Как работает

LOOK и MOVE бесплатные, поэтому программа сначала обходит всё, куда можно дойти по целым ходам, и делает LOOK в каждом зале. После этого остаётся один вопрос, какой из обвалившихся ходов на границе расчистить, или уже заканчивать.

Дни просто суммируются, так что порядок расчисток на итог не влияет. Для каждого хода достаточно понять, окупится он или нет.

**Дерево.** Для дерева это считается точно. Пусть F(x) это ожидаемая ценность поддерева зала x при оптимальной игре, c цена дня. Тогда

```
F(x) = profit(x) + sum по детям y [ p * F(y) + (1 - p) * max(0, F(y) - c) ]
```

Если ход цел, ребёнок достаётся бесплатно. Если обвален, либо платим c, либо бросаем поддерево. Поддеревья независимы, поэтому это и есть оптимальная стратегия, и считается она одним проходом снизу вверх.

**Общий граф.** Строится дерево самых надёжных путей (Дейкстра с весами −ln p), и на нём считается та же формула. Получается оценка снизу, потому что стратегия, которая ходит только по этому дереву, допустима и в исходном графе. Это стратегия `index`.

**Rollout.** На графе с циклами оценка снизу может недооценивать обходные пути. Поэтому по умолчанию для 6 лучших кандидатов разыгрываются случайные миры (неизвестные ходы сэмплируются по их p), и каждая ветка доигрывается стратегией `index`. Берётся кандидат с лучшим средним. Миры для всех кандидатов одни и те же, так сравнение меньше шумит.

Ещё есть простое отсечение. Если сумма всех недостигнутых залов не больше цены дня, программа сразу пишет END.

## Результаты

Все три прогона из условия совпадают с ответом. На 15 случайных картах по 40 залов средняя прибыль получилась такая

* noclear (ничего не расчищать) 225
* index 415
* rollout 415

На таких картах rollout почти не выигрывает, граф там близок к дереву, и index уже почти оптимален. Разница должна появляться на картах с большим количеством циклов.
